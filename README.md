# Парсер стоматологий без сайта (РФ)

Статус: **рабочая первая версия.** Собирает стоматологические клиники по
регионам РФ, отбирает те, у кого на карточке площадки (2ГИС / Яндекс.Карты /
Google Maps) не указан сайт, и складывает в SQLite + читаемый .xlsx —
это лиды под разработку сайта.

## Идея

Найти по России стоматологические клиники без собственного сайта —
потенциальные клиенты на разработку сайта. Сама рассылка/питч клиентам —
**вне этого репозитория и вне этой задачи**, см. ограничение ниже.

## Источники и их реальный статус (проверено 26.08.2026)

| Источник | Метод | Ключ/API нужен? | Статус с этой сети |
|---|---|---|---|
| **Яндекс.Карты** | обычный HTTP-запрос, серверный HTML содержит JSON-выдачу (`state-view`) | нет | ✅ работает, без блоков |
| **2ГИС** | Playwright, чтение состояния карточки фирмы (fetch + встроенный JSON) | нет (публичные ключи виджета сейчас отозваны самим 2ГИС) | ❌ жёсткий блок — редирект на `captcha.2gis.ru` с ЛЮБОГО запроса к 2gis.ru/2gis.kz/2gis.by с текущего IP, включая голую главную. Код рабочий, готов к запуску с другой сети |
| **Google Maps** | Playwright, обычная страница поиска | нет (Places API не используется) | ✅ отдаёт выдачу без капчи с текущей сети; дополнительный источник, ниже приоритетом |

Ни один источник не требует платного API-ключа. `.env.example` держит место
под ключи на случай, если платный доступ к 2ГИС/Google Places купят позже —
сейчас там пусто, и парсеры прекрасно работают без них.

**Важно:** блок 2ГИС — это реальная капча по IP, а не ошибка кода. Правило
задачи — не обходить капчу. Подробности, что именно проверено и что из этого
следует для владельца — ниже, раздел "2ГИС: что нашлось при сверке с RUSIMEX".

## Сверка настроек с RUSIMEX (27.08.2026, по прямому запросу владельца)

Владелец попросил не просто повторно использовать общую технику из
`RUSIMEX/leadgen/Hlebozavody_BY_KZ/scripts` (~190 скриптов, проект по лидам
хлебозаводов СНГ), а свериться с конкретными настройками, до которых тот
проект дошёл за месяцы итераций. Прочитано целиком: все *2gis*.py,
*yandex*.py, *gmaps*.py, `merge_lib.py`/`dedup_engine.py`/`round2_update_lib.py`/
`round3_lib.py`/`reconcile.py`, `QUALITY_RULES.md` и
`scripts/templates/2gis_deep_scan.md`. Что взято, что нет и почему —
по каждому источнику отдельно ниже; конкретные цифры и обоснование — прямо
в коде рядом с изменённым местом (см. docstring каждого файла), здесь —
сводка для быстрого чтения.

### 2ГИС: что нашлось при сверке с RUSIMEX

`scripts/templates/2gis_deep_scan.md` (проверено ими на 2gis.am/az/tj
18-19.08.2026, самый свежий документ по теме) описывает блокировку ИНОГО
рода, чем та, что встретилась здесь: у них — блокировка вглубь ОДНОГО и того
же поискового запроса после 4-6 страниц (`currentPage` зависает на 1, держится
часами), снимается сменой запроса. Взято оттуда и применено в
`src/scrapers/gis2.py`:
- ротация из 3 запросов вместо одного + глубокой пагинации (было: 1 запрос,
  до 5 страниц; стало: 3 запроса, до 2 страниц каждый);
- пауза 2.0-2.5с между запросами карточек (их проверенное значение против
  отдельного burst-лимита);
- fetch() + разбор встроенного JSON-состояния карточки вместо
  `page.goto()`-навигации на каждую карточку — задокументировано у них как
  быстрее и надёжнее клика/навигации.

Не перенесён языковой префикс `/ru/` в URL из их рецепта — он там нужен для
TLD, где русский не язык по умолчанию (2gis.am/az/tj); 2gis.ru и более старый
`harvest_2gis_v2.py` для 2gis.kz/by/ru его не используют — слепое копирование
сломало бы рабочий путь ради решения не нашей проблемы.

**Проверено отдельно 27.08.2026, чего в документах RUSIMEX нет:** блокировка
с ЭТОЙ сети наступает на ПЕРВОМ ЖЕ запросе (даже голая `2gis.ru/tyumen` без
единого поиска) — и одинаково на 2gis.ru, 2gis.kz И 2gis.by (проверено
напрямую через `requests`, без Playwright, все три редиректят на
`/museum` → капча). Значит, дело не в конкретном домене/TLD и не в
геолокации самой по себе — это блок по IP/сети целиком на уровне всей
платформы 2ГИС. Приёмы из `2gis_deep_scan.md` (ротация запроса, паузы)
решают ДРУГУЮ проблему и здесь не помогут, пока сеть не сменится — это
прямо написано в docstring `src/scrapers/gis2.py`, чтобы не создавать
ложного впечатления, что этими правками 2ГИС "починили".

**Про прокси/резидентные IP — владелец спросил конкретно.** Ни в одном из
~190 скриптов, ни в `QUALITY_RULES.md` нет ни единого упоминания
proxy/VPN/резидентного IP — весь код RUSIMEX работает через обычный
Playwright + системный Chrome, без какой-либо прокси-инфраструктуры. То есть
там НЕ решали сетевую часть проблемы прокси — либо она им не встречалась на
их тогдашней сети, либо не понадобилась. Единственная зацепка — по времени:
их последнее подтверждённо рабочее обращение к 2ГИС датировано 6-19.08.2026,
сегодняшний блок — 27.08.2026, три недели спустя, и уже сплошной с первого
запроса. Похоже на то, что IP/сеть этой машины за это время накопили у 2ГИС
блокировку (не исключено, что как раз от объёма ТОГО ЖЕ проекта) — то есть
это, скорее всего, проблема репутации конкретного адреса у антифрод-системы
2ГИС, а не принципиальный запрет по стране/провайдеру. **Практический вывод:
нужна другая сеть — смена VPN-выхода или резидентный прокси, если такой
заведут; это требование к сети, а не просто "подождать, пока появится
российский IP"** (дело не в геолокации, а в накопленной репутации адреса).

### Яндекс.Карты: настройки подтянуты, приём не менялся

`harvest_yandex.py`/`harvest_yandex_ext.py`/`harvest_yandex_ext2.py` используют
тот же приём (SSR `state-view`), что и здесь, но заметно медленнее: паузы
4.0-6.5с между страницами и 3.5-5.5с между запросами против 1.3-2.4с/1.5-2.8с,
что были здесь. Их значения проверены на 10 странах и десятках городов за
недели прогонов без единого упоминания капчи по Яндексу в `QUALITY_RULES.md`;
мой прогон (283 записи, один регион, один запуск) — доказательство куда
меньшего масштаба. Взял их пэйсинг: Москва даст на порядок больше карточек
за один запуск, чем Тюмень, и это не тот случай, где стоит проверять лимит
на практике первым. Глубину пагинации (8 страниц) НЕ уменьшил до их 4 —
собственный живой тест 26.08.2026 показал новые записи ещё на 5-й странице,
урезать значило бы терять реальные данные без доказанной для этого пункта
необходимости. Также перенесена их устойчивость к сбоям: раньше необработанное
исключение в одном городе роняло весь прогон региона — теперь (как у них)
город с ошибкой логируется и пропускается, прогон идёт дальше.

### Google Maps: настройки и приёмы подтянуты

`gmaps_kz_harvest.py`/`harvest_gmaps_by_kz.py`/`harvest_gmaps_uz_az.py`/
`gmaps_az.py`/`gmaps_uz_az_cards.py` — все пять используют один и тот же
набор (не разнобой, значит проверено многократно): `launch_persistent_context`
с сохраняемым профилем вместо "чистого" контекста на каждый запуск (было
здесь раньше), флаг `--lang=ru` в дополнение к `locale`, повтор при капче/блоке
3 попытки с бэкоффом `30×номер_попытки` секунд перед тем, как считать источник
реально заблокированным (было: сразу останов при первом же признаке блока),
пэйсинг 2.0-4.0с между навигациями (было 1.2-2.5с) и прокрутка ленты до 40
раундов с порогом стабильности 4 (было 25/3). Все перенесено в
`src/scrapers/google_maps.py`. НЕ перенесена их двухфазная схема
"индекс всех карточек по всем городам → отдельный обход карточек с
чекпоинтами на диск каждые 10" — это инфраструктура для многодневных прогонов
по 8+ странам; для одного запуска на один регион (минуты, не дни) она не
даёт выигрыша сверх того, что уже даёт запись в SQLite между городами.

### Дедуп между источниками: добавлен отдельный аудит, а не более умный ключ

После того как реальный прогон нашёл пропущенный дубль между источниками
(«Абсолют-Дент», см. ниже), проверено, как эту же проблему решили в RUSIMEX.
Ответ — НЕ более надёжная функция сравнения имён/адресов, а отдельный,
независимый скрипт-аудит ПОСЛЕ автоматического слияния: `audit_dupes_deep2.py`,
который сам `QUALITY_RULES.md` называет "основным аудитом дублей по ВСЕМ 10
странам". Причина явно записана там же: нечёткое сходство имён/вложенность
названий/общий сайт — "не хард-фейл: дают много ожидаемых ложных срабатываний
на легитимных сетях с филиалами... смотреть глазами". То есть даже в куда
более зрелом пайплайне такие сигналы НЕ сливают автоматически — тот же риск
здесь: у сети клиник может быть несколько РАЗНЫХ филиалов с похожими или
вложенными названиями в одном городе, которые нельзя схлопывать в один лид.

По этому образцу добавлен `src/audit_dupes.py` — отчёт (не автослияние) по
нечёткому сходству имён, вложенности названий, частичному пересечению
телефонов и общему домену в ссылке на карточку; печатается после каждого
прогона и доступен отдельно через `python main.py --audit-only`. Запущен на
уже собранных 76 лидах по Тюменской области: без доп. защиты дал 19 групп
"подозрений", 10 из которых оказались одним и тем же явлением — клиника,
буквально названная "Стоматология" (Тюмень, ул. Бакинских Комиссаров, 1),
"вложена" почти в любое другое название вида "Стоматология Х". Добавлена
защита `GENERIC_NAMES` (тот же приём, что и в `merge_lib.py`) — после неё
осталось 2 осмысленных кандидата на ручную проверку (см. тесты в
`tests/test_audit_dupes.py`, там же зафиксирован этот случай как регрессионный).

**Перепрогон после всех правок (27.08.2026), Тюменская область,
`python main.py --region tyumen --sources yandex_maps`:** 281 сырых записей
(было 283 — естественная погрешность живой выдачи, не регрессия), 275 прошли
фильтр (было 277), без сайта 71 (было 71 — точное совпадение), с телефоном
и/или email 67 (было 67 — точное совпадение), 65 лидов после слияния (было
65 — точное совпадение). Более медленный пэйсинг и добавленная устойчивость
к сбоям (см. выше) не изменили результат по существу — то, что и требовалось
подтвердить. Отдельно смоук-тест переписанного `google_maps.py`
(`launch_persistent_context` + повтор при блоке) на городе Заводоуковск —
5 карточек, извлечение имени/сайта/телефона отработало корректно.

## Что считается лидом

1. Название/рубрика похожи на стоматологическую клинику (`src/normalize.py:is_dental_clinic`) —
   отсекает зуботехнические лаборатории, склады расходников, курсы.
2. На карточке площадки **нет поля "сайт"** — сигнал "без сайта". Это сигнал
   уровня площадки, не 100%-й факт: у клиники физически может быть сайт,
   который она просто не привязала к карточке на 2ГИС/Яндексе/Google —
   встречается на практике, поэтому это **вероятностный, а не точный** признак
   (см. раздел "Точность" ниже).
3. Есть хотя бы один нормализуемый российский телефон и/или email.
   Email на картах — редкость: ни Яндекс.Карты, ни (в основном) 2ГИС, ни Google
   Maps карточка организации email не публикует. В реальном прогоне почти
   все лиды — с телефоном, без email. Это не баг сборщика, а честное
   ограничение источников — держим в уме при планировании охвата.

## Точность сигнала "без сайта" — ПРОВЕРЕНО, и цифра неприятная

Ложноположительные (у клиники ЕСТЬ сайт, но карточка его не показывает)
возможны, когда:
- сайт указан не в стандартном поле, а только в описании/соцсетях карточки;
- клиника ведёт сайт через агрегатор (Instagram/VK-визитку), который источник
  не считает "сайтом" в своём отдельном поле;
- площадка отстаёт от реальности (сайт появился недавно, карточка не обновилась).

Это не теория: **10 случайных лидов из реального прогона по Тюменской области
проверены вручную обычным веб-поиском (название + город)** — у скольких
на самом деле есть сайт, который просто не привязан к карточке Яндекс.Карт.

| Клиника | Город | По Яндекс.Картам | На самом деле |
|---|---|---|---|
| Доверие | Тюмень | без сайта | **сайт есть** — доверие-стоматология.рф |
| Энже | Тобольск | без сайта | **сайт есть** — enzhe72.ru |
| Зубная мудрость | Тюмень | без сайта | **сайт есть** — зубнаямудрость.рф |
| Премьер Дентал | Тюмень | без сайта | **сайт есть** — premierdental.ru |
| Family Smile | Тюмень | без сайта | **сайт есть** — family-smile.ru |
| Абсолют-Дент | Тюмень | без сайта | **сайт есть** — absolut-dent.ru |
| Сириус | Тобольск | без сайта | похоже, сайт есть (не 100% — тёзка в Тюмени/Казани, могла попасться не та ссылка) |
| Макси-Дент | Тюмень | без сайта | сайта не нашлось (только агрегаторы) |
| Стомадент | Тобольск | без сайта | сайта не нашлось (только агрегаторы) |
| Radent | Тобольск | без сайта | сайта не нашлось (только агрегаторы) |

**Итог: 6-7 из 10 (60-70%) на самом деле — ложные срабатывания: сайт у
клиники есть, просто не привязан к карточке на Яндекс.Картах.** Похоже,
у стоматологий это системно: они охотнее заводят сайт (лендинг под запись),
чем аккуратно поддерживают все поля карточки на всех картах одновременно.

**Практический вывод для владельца:** брать эту базу как список "точно без
сайта" **нельзя** — реальная доля "действительно без сайта" в текущей выборке
похожа на 30-40%, а не на 100%, которые подразумевает колонка `has_website`.
Прежде чем передавать базу в работу питчерам, нужен ещё один шаг: по каждому
кандидату — быстрая проверка обычным веб-поиском (название + город + "сайт"),
и в базу идут только те, для кого поиск ничего не подтвердил. Это отдельная
задача, не автоматизированная в текущей версии (WebSearch — не то, что можно
дёшево гонять на сотни лидов без дополнительной настройки), но именно она,
а не сам сбор данных — теперь главное узкое место точности.

## Реальный прогон (proof of concept, 26.08.2026)

`python main.py --region tyumen --sources yandex_maps` — Тюменская область,
5 городов (Тюмень, Тобольск, Ишим, Ялуторовск, Заводоуковск), 4 поисковых
запроса на город:

| Шаг | Количество |
|---|---|
| Сырых карточек с Яндекс.Карт | 283 |
| Прошли фильтр "это стоматология" | 277 |
| Из них без поля "сайт" на карточке | 71 |
| Из них с телефоном и/или email | 67 |
| После слияния дублей между запросами | **65 лидов в базе** |
| С телефоном | 65 (100%) |
| С email | 0 (0%) — ожидаемо, см. выше |

По распределению: Тюмень 37, Тобольск 15, Ишим 5, Ялуторовск 4, Заводоуковск 4.

Следом отдельно прогнан `google_maps` по городу Тюмень (80 карточек в ленте,
15 без сайта, 12 после внутреннего слияния дублей) и добавлен в ту же базу —
проверить слияние между источниками на реальных данных, не только в теории.

### Слияние между источниками — тоже проверено, тоже нашлись дыры

Из 12 новых лидов от Google Maps ни один не слился автоматически с уже
собранными 65 из Яндекс.Карт (0 совпадений по `dedupe_key`). Проверка вручную
нашла минимум один случай, когда это **одна и та же организация** —
«Абсолют-Дент» (Майский проезд/проезд, 5к2, Тюмень):
- у записи с Google Maps название на карточке было
  `Абсолют-Дент | Стоматология Тюмень | Детский стоматолог, брекеты, имплантация`
  (SEO-название целиком в поле "название организации" — так бывает на Google
  Business Profile) — из-за этого `name_key` не совпадал с чистым «Абсолют-Дент»
  на Яндексе;
- и адрес отформатирован по-разному: Яндекс пишет микрорайон («Восточный»),
  Google — этаж («2 этаж»); упрощённый разбор адреса в этом проекте не
  предназначен для такого разнобоя, из-за чего «улица+дом»-ключ тоже разошёлся;
- и телефоны, что характерно, **тоже разные** (мобильный на Яндексе, городской
  на Google) — то есть даже эталонный сигнал "общий телефон" здесь бы не помог.

Первую причину (SEO-название) поправили в `src/scrapers/google_maps.py` —
теперь текст после `" | "` в названии с карточки Google Maps отбрасывается.
Эту конкретную пару строк слили вручную и оставили пометку в поле `notes`
(см. `src/db.py`, было бы неверно тихо оставить дубль в базе, раз уж он найден).
Разбор адреса (микрорайон против этажа) — не чинили: более надёжный парсер
адреса — заметно больший объём работы, а не однострочная правка, честно
фиксируем как known limitation.

**Вывод:** дедуп по имени+адресу+телефону (см. `src/dedup.py`) ловит дубли
внутри одного источника и в пределах одного запуска, но **не гарантия отсутствия
дублей между источниками** при сильно разном форматировании карточек — это
подтверждено на реальном кейсе, не гипотетически. Если база пойдёт в работу
питчерам, имеет смысл разово визуально пролистать итоговый .xlsx (76 строк
по Тюменской области — вполне читаемый объём) и глазами убрать очевидные
повторы, а не доверять колонке `source` на 100%. Дополнительно — теперь
`python main.py --audit-only` печатает список кандидатов на повторную проверку
(см. раздел "Сверка настроек с RUSIMEX" ниже, там же — почему это отчёт,
а не автослияние).

**Важный вывод из Тюмени, до Краснодара/Москвы:** запуск источников ПОРОЗНЬ
(как здесь) отдаёт кросс-источниковое слияние на откуп более слабому пути —
`db.upsert_lead` сравнивает только точный `dedupe_key`, без фолбэка по
телефону. Запуск источников ВМЕСТЕ одной командой (`--sources
yandex_maps,google_maps`) идёт через `dedup.merge_raw_leads`, где есть и
точный ключ, и слияние по общему телефону — это и подтвердилось на
Краснодаре ниже (реальные кросс-источниковые слияния появились, чего не было
здесь). Вывод для дальнейших регионов: запускать источники вместе одной
командой, а не порознь.

## Реальные прогоны: Краснодарский край и Москва (27.08.2026)

Оба прогона — `python main.py --region X --sources yandex_maps,google_maps`
(2ГИС пропущен явно: сеть по-прежнему блокирует платформу целиком, см. выше —
запускать его означало бы просто ждать капчу на первом же запросе, а не
собирать данные). Настройки — уже после сверки с RUSIMEX (консервативный
пэйсинг Яндекса, устойчивость к сбоям по городам, персистентный профиль +
повтор с бэкоффом у Google Maps).

По городам (лидов после слияния): Сочи 82, Новороссийск 61, Краснодар 40,

По источникам: 157 только с Яндекс.Карт, 70 только с Google Maps, **38

там кросс-источниковых слияний не было ни одного, именно потому что там
источники гонялись раздельно; здесь, вместе, слияние по общему телефону
сработало на практике, не только в тестах).

**Аудит на возможные дубли (`--audit-only`) сразу вскрыл повтор той же
проблемы, что и в Тюмени**, только другое склонение: клиника, буквально
названная "Стоматолог" (без "-ия"), нашлась в Сочи И отдельно в Анапе — обе
"вложились" почти в каждое название вида "Стоматолог Х" в своём городе,
дав 14 из 29 найденных групп только за счёт этого одного слова. Слово
добавлено в `GENERIC_NAMES` (см. `src/audit_dupes.py`, коммит `cdc6d6e`) —
после этого осталось 9 осмысленных кандидатов, среди них минимум один явный
реальный дубль: «Doctor Kim» / «Стоматология Doctor Kim» / «Стоматологическая
клиника Добрый Доктор» в Армавире — все три на одном телефоне
+7 918 074-73-73 и одном адресе (Новороссийская, 90б). Эти 9 намеренно
оставлены как кандидаты на ручную проверку, не слиты автоматически — та же
логика, что и в README выше (легитимные сети с филиалами дают ожидаемые
ложные срабатывания на нечётких сигналах).

### Москва — 1 город, но с оговоркой

| Шаг | Количество |
|---|---|
| Сырых карточек (оба источника) | 546 |
| Прошли фильтр "это стоматология" | 545 |
| Из них без поля "сайт" на карточке | 15 |
| Из них с телефоном и/или email | 15 |
| После слияния дублей | **14 лидов в базе** |
| С телефоном | 14 (100%) |
| С email | 0 (0%) |

Аудит на дубли — ничего не нашёл (объём слишком мал для ложных срабатываний).

**Главное, на что стоит обратить внимание владельцу: доля "без сайта" в
Москве — 15/545 ≈ 2.8%, против ~25-28% в Тюмени и Краснодарском крае.**
Это не аномалия сборщика — правдоподобное объяснение: Москва настолько
конкурентный рынок стоматологии, что сайт клиники там — почти обязательный
минимум, а не опция. Практический вывод: Москва (в её нынешнем виде — один
город целиком) вряд ли даёт много лидов именно под эту задачу ("нет сайта"),
сколько бы городов ни добавили в объезд — рынок структурно другой, чем
Тюмень/Краснодарский край. 14 найденных лидов — достаточно маленький список,
чтобы владелец мог сам вручную перепроверить каждый перед передачей в работу.

Отдельная оговорка по охвату: `MAX_PAGES_PER_QUERY = 8` в `yandex_maps.py`
(см. "Сверка настроек с RUSIMEX" выше) — в Москве все 4 запроса упирались в
этот потолок (125/144/110/87 новых карточек на запрос, без явного спада к
последней странице, в отличие от малых городов Тюменской области, где показ
падал до нуля раньше потолка). Значит, в Москве реальное число стоматологий
на Яндекс.Картах заметно больше 545 — прогон снял верхний срез выдачи, не
исчерпывающий список. Для города такого масштаба это ожидаемо и не критично
для текущей задачи (даже полный охват вряд ли сильно поднимет долю "без
сайта" выше нескольких процентов), но владелец должен знать, что цифра 545
— не "все стоматологии Москвы", а частичная выборка.

### Открытый вопрос: Московская область — её нет в конфиге

`config/regions.py` сейчас содержит только `"moscow"` = город Москва.
**Московская область как отдельный регион не заведена** — это осознанно не
сделано за владельца: агент не должен сам выбирать список городов для
области (Химки, Балашиха, Подольск, Мытищи, Коломна и далее — десятки
городов очень разного размера, выбор существенно влияет на объём работы и
результат). Нужно решение владельца: считать ли Московскую область отдельным
регионом (структурно она может вести себя иначе, чем сама Москва — судя по
находке выше про Москву, областные города вполне могут оказаться ближе по
паттерну к Тюмени/Краснодару, чем к самой Москве, раз они менее насыщены
конкуренцией) и, если да, какие города в неё включить. Как только список
придёт — это одна правка `config/regions.py` (см. раздел "Новый регион"
ниже), код трогать не нужно.

## Установка

```bash
pip install -r requirements.txt
playwright install chromium   # нужно только для источников 2gis / google_maps
```

## Запуск

```bash
# список регионов из конфига
python main.py --list-regions

# один регион, только Яндекс.Карты (самый быстрый и надёжный источник)
python main.py --region tyumen --sources yandex_maps

# все источники по умолчанию (yandex_maps,2gis,google_maps — 2gis откроет
# видимое окно Chrome, это ожидаемо, headless тут не используется)
python main.py --region moscow

# несколько регионов за один запуск
python main.py --region tyumen --region krasnodar --sources yandex_maps

# пересобрать .xlsx из уже накопленной SQLite, без единого сетевого запроса
python main.py --export-only

# проверить уже накопленные данные на возможные дубли между источниками,
# без единого сетевого запроса (см. src/audit_dupes.py)
python main.py --audit-only
```

Результат:
- `data/leads.sqlite3` — основное хранилище, накапливается между запусками
  (повторный запуск того же региона не плодит дубли — лид с тем же
  `dedupe_key` дозаполняется новым телефоном/источником, см. `src/db.py`)
- `out/стоматологии_без_сайта.xlsx` — лист "Сводка" + один лист на регион

Оба пути — **в .gitignore**, в публичный репозиторий не попадают
(правило портфеля "GitHub = процесс, не данные" — так же настроено в
RUSIMEX и pc-price-tracker).

## Новый регион

Правь только `config/regions.py` — добавь новый ключ в `REGIONS` со списком
городов. Код парсеров/пайплайна трогать не нужно, они читают список городов
из конфига. Регион с `"confirmed": False` можно запускать явным `--region` —
это просто пометка "владелец ещё не подтвердил", а не техническое ограничение.

## Схема лида (`src/models.py`)

`dedupe_key, org_name, category, region, city, address, phone, email,
has_website, source, source_url, scraped_at, notes`

`phone`/`source`/`source_url` — списки через `"; "`, если лид нашёлся в
нескольких источниках или с несколькими телефонами (слияние — `src/dedup.py`,
по точному совпадению имя+город+улица/дом и по общему телефону в одном
городе, с защитой от "общего номера колл-центра" — тот же принцип, что
в проверенном на практике `RUSIMEX/leadgen/Hlebozavody_BY_KZ/scripts/dedup_engine.py`).

## Важное ограничение (не снято)

Рассылка/питч с формулировкой в духе «Минздрав и РКН теперь требуют сайт,
иначе штраф» **не отправляется и не пишется**, пока не проверена точная
юридическая формулировка требования. Это отдельная задача, ещё не
выполненная — см. память по этому проекту. Этот репозиторий её не
затрагивает вообще: он только собирает данные.

## Структура проекта

```
config/regions.py       — список регионов и городов (единственное, что обычно нужно править)
src/scrapers/            — по одному модулю на источник (yandex_maps, gis2, google_maps)
src/normalize.py         — телефон/email/адрес в чистый вид, фильтр "это стоматология"
src/dedup.py             — слияние дублей между источниками (автоматическое, консервативное)
src/audit_dupes.py       — отдельный отчёт по возможным дублям (нечёткие сигналы, не автослияние)
src/db.py                — SQLite-хранилище
src/export_xlsx.py       — .xlsx-экспорт
src/pipeline.py           — склеивает всё вместе на один регион
main.py                   — CLI
data/, out/                — сгенерированные данные (gitignored)
```
