# Парсер стоматологий без сайта (РФ)

Статус: **рабочая первая версия.** Собирает стоматологические клиники по
регионам РФ, отбирает те, у кого на карточке площадки (2ГИС / Яндекс.Карты /
Google Maps) не указан сайт, и складывает в SQLite + читаемый .xlsx —
это лиды под разработку сайта.

## Идея

Найти по России стоматологические клиники без собственного сайта —
потенциальные клиенты на разработку сайта. Сама рассылка/питч клиентам —
**вне этого репозитория и вне этой задачи**, см. ограничение ниже.

## Источники и их реальный статус (проверено 26.08.2026)

| Источник | Метод | Ключ/API нужен? | Статус с этой сети |
|---|---|---|---|
| **Яндекс.Карты** | обычный HTTP-запрос, серверный HTML содержит JSON-выдачу (`state-view`) | нет | ✅ работает, без блоков |
| **2ГИС** | Playwright, чтение `window.initialState` карточки фирмы | нет (публичные ключи виджета сейчас отозваны самим 2ГИС) | ❌ жёсткий блок — `captcha.2gis.ru` на любой поисковый запрос с текущего IP. Код рабочий, готов к запуску с российского IP/сети |
| **Google Maps** | Playwright, обычная страница поиска | нет (Places API не используется) | ✅ отдаёт выдачу без капчи с текущей сети; дополнительный источник, ниже приоритетом |

Ни один источник не требует платного API-ключа. `.env.example` держит место
под ключи на случай, если платный доступ к 2ГИС/Google Places купят позже —
сейчас там пусто, и парсеры прекрасно работают без них.

**Важно:** блок 2ГИС — это реальная капча по IP, а не ошибка кода. Правило
задачи — не обходить капчу. Запуск `python main.py --region X --sources 2gis`
с российского IP (или после смены сети) должен заработать тем же кодом без
правок; с нынешней сети он честно остановится и запишет причину в лог,
не подставляя выдуманные данные.

## Что считается лидом

1. Название/рубрика похожи на стоматологическую клинику (`src/normalize.py:is_dental_clinic`) —
   отсекает зуботехнические лаборатории, склады расходников, курсы.
2. На карточке площадки **нет поля "сайт"** — сигнал "без сайта". Это сигнал
   уровня площадки, не 100%-й факт: у клиники физически может быть сайт,
   который она просто не привязала к карточке на 2ГИС/Яндексе/Google —
   встречается на практике, поэтому это **вероятностный, а не точный** признак
   (см. раздел "Точность" ниже).
3. Есть хотя бы один нормализуемый российский телефон и/или email.
   Email на картах — редкость: ни Яндекс.Карты, ни (в основном) 2ГИС, ни Google
   Maps карточка организации email не публикует. В реальном прогоне почти
   все лиды — с телефоном, без email. Это не баг сборщика, а честное
   ограничение источников — держим в уме при планировании охвата.

## Точность сигнала "без сайта" — ПРОВЕРЕНО, и цифра неприятная

Ложноположительные (у клиники ЕСТЬ сайт, но карточка его не показывает)
возможны, когда:
- сайт указан не в стандартном поле, а только в описании/соцсетях карточки;
- клиника ведёт сайт через агрегатор (Instagram/VK-визитку), который источник
  не считает "сайтом" в своём отдельном поле;
- площадка отстаёт от реальности (сайт появился недавно, карточка не обновилась).

Это не теория: **10 случайных лидов из реального прогона по Тюменской области
проверены вручную обычным веб-поиском (название + город)** — у скольких
на самом деле есть сайт, который просто не привязан к карточке Яндекс.Карт.

| Клиника | Город | По Яндекс.Картам | На самом деле |
|---|---|---|---|
| Доверие | Тюмень | без сайта | **сайт есть** — доверие-стоматология.рф |
| Энже | Тобольск | без сайта | **сайт есть** — enzhe72.ru |
| Зубная мудрость | Тюмень | без сайта | **сайт есть** — зубнаямудрость.рф |
| Премьер Дентал | Тюмень | без сайта | **сайт есть** — premierdental.ru |
| Family Smile | Тюмень | без сайта | **сайт есть** — family-smile.ru |
| Абсолют-Дент | Тюмень | без сайта | **сайт есть** — absolut-dent.ru |
| Сириус | Тобольск | без сайта | похоже, сайт есть (не 100% — тёзка в Тюмени/Казани, могла попасться не та ссылка) |
| Макси-Дент | Тюмень | без сайта | сайта не нашлось (только агрегаторы) |
| Стомадент | Тобольск | без сайта | сайта не нашлось (только агрегаторы) |
| Radent | Тобольск | без сайта | сайта не нашлось (только агрегаторы) |

**Итог: 6-7 из 10 (60-70%) на самом деле — ложные срабатывания: сайт у
клиники есть, просто не привязан к карточке на Яндекс.Картах.** Похоже,
у стоматологий это системно: они охотнее заводят сайт (лендинг под запись),
чем аккуратно поддерживают все поля карточки на всех картах одновременно.

**Практический вывод для владельца:** брать эту базу как список "точно без
сайта" **нельзя** — реальная доля "действительно без сайта" в текущей выборке
похожа на 30-40%, а не на 100%, которые подразумевает колонка `has_website`.
Прежде чем передавать базу в работу питчерам, нужен ещё один шаг: по каждому
кандидату — быстрая проверка обычным веб-поиском (название + город + "сайт"),
и в базу идут только те, для кого поиск ничего не подтвердил. Это отдельная
задача, не автоматизированная в текущей версии (WebSearch — не то, что можно
дёшево гонять на сотни лидов без дополнительной настройки), но именно она,
а не сам сбор данных — теперь главное узкое место точности.

## Реальный прогон (proof of concept, 26.08.2026)

`python main.py --region tyumen --sources yandex_maps` — Тюменская область,
5 городов (Тюмень, Тобольск, Ишим, Ялуторовск, Заводоуковск), 4 поисковых
запроса на город:

| Шаг | Количество |
|---|---|
| Сырых карточек с Яндекс.Карт | 283 |
| Прошли фильтр "это стоматология" | 277 |
| Из них без поля "сайт" на карточке | 71 |
| Из них с телефоном и/или email | 67 |
| После слияния дублей между запросами | **65 лидов в базе** |
| С телефоном | 65 (100%) |
| С email | 0 (0%) — ожидаемо, см. выше |

По распределению: Тюмень 37, Тобольск 15, Ишим 5, Ялуторовск 4, Заводоуковск 4.

Следом отдельно прогнан `google_maps` по городу Тюмень (80 карточек в ленте,
15 без сайта, 12 после внутреннего слияния дублей) и добавлен в ту же базу —
проверить слияние между источниками на реальных данных, не только в теории.

### Слияние между источниками — тоже проверено, тоже нашлись дыры

Из 12 новых лидов от Google Maps ни один не слился автоматически с уже
собранными 65 из Яндекс.Карт (0 совпадений по `dedupe_key`). Проверка вручную
нашла минимум один случай, когда это **одна и та же организация** —
«Абсолют-Дент» (Майский проезд/проезд, 5к2, Тюмень):
- у записи с Google Maps название на карточке было
  `Абсолют-Дент | Стоматология Тюмень | Детский стоматолог, брекеты, имплантация`
  (SEO-название целиком в поле "название организации" — так бывает на Google
  Business Profile) — из-за этого `name_key` не совпадал с чистым «Абсолют-Дент»
  на Яндексе;
- и адрес отформатирован по-разному: Яндекс пишет микрорайон («Восточный»),
  Google — этаж («2 этаж»); упрощённый разбор адреса в этом проекте не
  предназначен для такого разнобоя, из-за чего «улица+дом»-ключ тоже разошёлся;
- и телефоны, что характерно, **тоже разные** (мобильный на Яндексе, городской
  на Google) — то есть даже эталонный сигнал "общий телефон" здесь бы не помог.

Первую причину (SEO-название) поправили в `src/scrapers/google_maps.py` —
теперь текст после `" | "` в названии с карточки Google Maps отбрасывается.
Эту конкретную пару строк слили вручную и оставили пометку в поле `notes`
(см. `src/db.py`, было бы неверно тихо оставить дубль в базе, раз уж он найден).
Разбор адреса (микрорайон против этажа) — не чинили: более надёжный парсер
адреса — заметно больший объём работы, а не однострочная правка, честно
фиксируем как known limitation.

**Вывод:** дедуп по имени+адресу+телефону (см. `src/dedup.py`) ловит дубли
внутри одного источника и в пределах одного запуска, но **не гарантия отсутствия
дублей между источниками** при сильно разном форматировании карточек — это
подтверждено на реальном кейсе, не гипотетически. Если база пойдёт в работу
питчерам, имеет смысл разово визуально пролистать итоговый .xlsx (76 строк
по Тюменской области — вполне читаемый объём) и глазами убрать очевидные
повторы, а не доверять колонке `source` на 100%.

## Установка

```bash
pip install -r requirements.txt
playwright install chromium   # нужно только для источников 2gis / google_maps
```

## Запуск

```bash
# список регионов из конфига
python main.py --list-regions

# один регион, только Яндекс.Карты (самый быстрый и надёжный источник)
python main.py --region tyumen --sources yandex_maps

# все источники по умолчанию (yandex_maps,2gis,google_maps — 2gis откроет
# видимое окно Chrome, это ожидаемо, headless тут не используется)
python main.py --region moscow

# несколько регионов за один запуск
python main.py --region tyumen --region krasnodar --sources yandex_maps

# пересобрать .xlsx из уже накопленной SQLite, без единого сетевого запроса
python main.py --export-only
```

Результат:
- `data/leads.sqlite3` — основное хранилище, накапливается между запусками
  (повторный запуск того же региона не плодит дубли — лид с тем же
  `dedupe_key` дозаполняется новым телефоном/источником, см. `src/db.py`)
- `out/стоматологии_без_сайта.xlsx` — лист "Сводка" + один лист на регион

Оба пути — **в .gitignore**, в публичный репозиторий не попадают
(правило портфеля "GitHub = процесс, не данные" — так же настроено в
RUSIMEX и pc-price-tracker).

## Новый регион

Правь только `config/regions.py` — добавь новый ключ в `REGIONS` со списком
городов. Код парсеров/пайплайна трогать не нужно, они читают список городов
из конфига. Регион с `"confirmed": False` можно запускать явным `--region` —
это просто пометка "владелец ещё не подтвердил", а не техническое ограничение.

## Схема лида (`src/models.py`)

`dedupe_key, org_name, category, region, city, address, phone, email,
has_website, source, source_url, scraped_at, notes`

`phone`/`source`/`source_url` — списки через `"; "`, если лид нашёлся в
нескольких источниках или с несколькими телефонами (слияние — `src/dedup.py`,
по точному совпадению имя+город+улица/дом и по общему телефону в одном
городе, с защитой от "общего номера колл-центра" — тот же принцип, что
в проверенном на практике `RUSIMEX/leadgen/Hlebozavody_BY_KZ/scripts/dedup_engine.py`).

## Важное ограничение (не снято)

Рассылка/питч с формулировкой в духе «Минздрав и РКН теперь требуют сайт,
иначе штраф» **не отправляется и не пишется**, пока не проверена точная
юридическая формулировка требования. Это отдельная задача, ещё не
выполненная — см. память по этому проекту. Этот репозиторий её не
затрагивает вообще: он только собирает данные.

## Структура проекта

```
config/regions.py       — список регионов и городов (единственное, что обычно нужно править)
src/scrapers/            — по одному модулю на источник (yandex_maps, gis2, google_maps)
src/normalize.py         — телефон/email/адрес в чистый вид, фильтр "это стоматология"
src/dedup.py             — слияние дублей между источниками
src/db.py                — SQLite-хранилище
src/export_xlsx.py       — .xlsx-экспорт
src/pipeline.py           — склеивает всё вместе на один регион
main.py                   — CLI
data/, out/                — сгенерированные данные (gitignored)
```
